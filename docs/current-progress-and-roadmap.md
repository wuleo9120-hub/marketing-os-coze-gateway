# 当前进度和下一步路线图

## 当前结论

系统已经完成 MVP 工程骨架和虚拟商家全链路演示，可以用来验证“提交资料 -> 多 Agent 拆解 -> 生成内容和发布包 -> 模拟发布 -> 指标回流 -> 客服回复 -> 转人工 -> 复盘优化”的闭环。

它还不是完整生产系统。真实抖音、小红书、视频号发布，以及微信侧无人值守消息，需要官方接口、服务商权限或人工确认流程。

## 已完成

1. 系统地基
   - 本地 API 和前端中控台。
   - 本地 JSON 持久化。
   - 任务板、审批中心、工具注册中心。

2. 多 Agent 协作
   - Orchestrator 总控。
   - Brand Strategy、Platform Research、Content Creation、Video Production、Publishing Ops、Customer Service、Data Review、Sales Assist 等 Agent。
   - Agent 执行前检索共同记忆和知识库。

3. 模型路由
   - Codex GPT-5.5 supervised：总控、品牌策略、数据复盘、销售辅助。
   - MiniMax-M2.7：平台研究、内容生成、视频生产、发布运营、客服。
   - 没有真实 gateway 时自动降级为 stub 或 supervised handoff。

4. Hermes / OpenClaw 边界
   - Hermes：长期记忆、自我复盘、优化建议。
   - OpenClaw：受控外部工具执行和浏览器辅助。
   - 两者都被治理层限制，不能自主进行无关任务、高风险发布、私信、加好友、收款或签约。

5. 营销闭环 MVP
   - 内容资产。
   - 多平台发布包。
   - 平台发布 stub。
   - 指标回流和策略复盘。
   - 虚拟商家“云朵烘焙工作室”全流程。

6. 客户承接
   - CRM 线索。
   - AI 客服回复草稿。
   - 高意向识别和转人工。
   - 企业微信 stub。
   - 个人微信辅助承接模式。

7. 安全治理
   - 高风险动作审批。
   - Agent 预算和外部工具预算。
   - 本地 API 写入保护。
   - 敏感配置脱敏。
   - 内存写入防密钥泄漏。

## 现在可以用

- 打开中控台，提交商家资料和知识库。
- 让系统生成营销计划、内容资产、发布包。
- 用虚拟数据跑完整流程。
- 使用个人微信二维码或手动 CRM 方式承接客户。
- 让 AI 生成客服回复草稿和转人工摘要。
- 查看 Agent 自我优化和自主循环结果。

## 现在还不能完全自动化

- 不能在没有官方权限时无人值守发布到抖音、小红书、视频号。
- 不能无人值守操作个人微信自动加好友、自动发私信或群发。
- 还没有生产级数据库、多商家隔离、部署、日志和成本面板。
- 新版本地服务端口需要批准 `./scripts/dev-server.sh` 固定脚本后才能在浏览器验证。

## 下一步任务安排

### P0：让进度面板可见

目标：批准并启动固定脚本。

```bash
./scripts/dev-server.sh 8791
```

完成后打开：

```text
http://127.0.0.1:8791
```

结果：可以看到“项目进度”和“真实接口准备度”面板。

### P0：个人微信承接前端

目标：在中控台展示个人微信二维码、创建个微线索、输入客户消息并生成 AI 回复草稿。

状态：已完成。

配置：

```text
WEIXIN_PERSONAL_QR_URL=
WEIXIN_PERSONAL_ACCOUNT_LABEL=
```

试用流程：

1. 把个人微信二维码放到可访问 URL，并写入 `WEIXIN_PERSONAL_QR_URL`。
2. 在新版中控台查看“个人微信承接”面板。
3. 客户主动添加个人微信后，在面板里记录客户称呼和微信备注。
4. 把客户咨询内容粘贴到“生成个微回复草稿”。
5. 人工检查草稿后，在个人微信里发送。
6. 出现报价、合同、付款等高意向信号时，系统会创建转人工记录。

### P0：个人微信真实试用流程

目标：用真实商家或虚拟商家的个人微信二维码跑一轮半自动承接。

注意：个人微信模式不会自动加好友、自动私信或群发。它只负责二维码承接、线索记录、回复草稿、意向判断和转人工摘要。

### P1：商家入驻向导

目标：把商家提交资料变成结构化知识库和共同记忆。

状态：已完成。

需要字段：

- 品牌介绍
- 产品/服务
- 客户画像
- 常见问题
- 价格范围
- 禁用词和合规要求
- 平台账号
- 微信承接方式

提交后系统会自动生成：

- 品牌画像记忆
- 转化和承接边界记忆
- 内容语气和平台方向记忆
- 品牌/产品知识文档
- 客服 FAQ 和成交边界知识文档
- 平台内容策略知识文档

### P1：基于商家资料生成首轮营销计划

目标：商家资料提交后，一键生成首周选题、内容资产、发布包、客服话术和复盘指标。

状态：已完成。

生成内容：

- 首周营销计划记忆。
- 首轮营销计划知识文档。
- 首轮客服话术知识文档。
- 每个平台一条内容资产。
- 每条内容资产对应一个发布包。
- 播放、点赞、评论、线索等指标模板。
- 首周 CTA A/B 测试实验假设。

### P1：首轮计划执行和人工确认

目标：人工审核内容资产和发布包，确认后发布到对应平台；发布后回填真实指标。

状态：已完成。

当前支持：

- 查看发布审核队列。
- 按 `publishing_job_id` 标记人工已发布。
- 回填发布链接。
- 回填初始播放、点赞、评论和线索。
- 自动把发布状态写入发布任务和内容资产。
- 自动生成发布工作流记忆。

### P1：真实指标复盘循环

目标：真实发布 24 小时后回填指标，触发策略复盘并生成下一轮优化计划。

状态：已完成。

当前支持：

- 读取人工发布和回填指标。
- 识别表现最好的内容/实体。
- 生成策略复盘记忆。
- 生成下一轮优化建议。
- 创建下一轮实验假设。
- 创建下一轮内容任务和数据复盘任务。

### P1：下一轮内容任务执行

目标：复盘循环生成任务后，一键执行任务队列，产出下一轮内容资产和发布包。

状态：已完成。

当前支持：

- 只执行来源为 `metric_review_loop` 的 queued 任务。
- 生成下一轮内容资产。
- 自动为新内容资产生成发布包。
- 写入下一轮任务执行记忆。
- 避免误执行其它高风险任务。

### P1：真实 connector 或生产化路线选择

目标：根据当前是否已经拿到平台资质，选择下一阶段路线。

选项：

- 如果已经拿到抖音开放平台或企业微信权限，优先接真实 connector。
- 如果还没拿到权限，优先做数据库、部署、账号隔离和成本监控。

状态：下一步。

所需配置：

```text
DOUYIN_CLIENT_KEY=

```

### P2：数据库和生产化

目标：把本地 JSON 存储升级为 PostgreSQL + pgvector，支持多商家、长期记忆和部署运行。

状态：已开始。

当前支持：

- `GET /api/production/readiness` 生产化准备度检查。
- 中控台“生产化准备度”面板。
- PostgreSQL/pgvector 目标 schema 蓝图：`infra/postgres/schema.sql`。
- PostgreSQL migration runner：`node scripts/postgres-migrate.mjs --dry-run`。
- 环境变量清单：数据库、队列、对象存储、认证、监控、成本、多商家隔离。
- Store Adapter 选择器：`STORE_ADAPTER=json` 默认，`STORE_ADAPTER=postgres` 需迁移后显式启用。
- PostgreSQL Store Adapter 已具备 SQL-backed load/persist，当前采用整库 state 事务刷新方式，适合生产化前的第一阶段迁移验证。
- 多商家 Workspace 隔离第一阶段：写入带 `workspace_id`，列表/知识库搜索/商家入驻/首轮计划按 workspace 过滤。
- 前端中控台商家切换器：可新增/切换商家空间，主要 API 自动带 `workspace_id` 和 `x-workspace-id`。
- Coze 前台接入：`/api/coze/*` 受控网关、OpenAPI 插件描述和配置指南已完成。
- Render/Docker 首版部署包：`Dockerfile`、`render.yaml`、部署 token 生成器和 Render 部署指南已完成。

下一步：

- 部署一个 HTTPS Marketing OS API 地址，并在 Coze Plugin 中导入 `integrations/coze/openapi.yaml`。
- 配置 `DATABASE_URL` 后执行 `node scripts/postgres-migrate.mjs --apply`。
- 用一份测试数据库验证 `STORE_ADAPTER=postgres ENABLE_POSTGRES_STORE_ADAPTER=true` 启动。
- 把真实 connector 凭证、平台账号和预算策略进一步绑定到 workspace。

## 推荐顺序

1. 先批准固定启动脚本，验证新版中控台。
2. 配置个人微信二维码，跑个人微信真实试用流程。
3. 选择真实 connector 或生产化路线。
4. 并行申请企业微信和抖音开放平台权限。
5. 拿到权限后接真实 connector。
6. 没拿到权限前先做数据库、部署和成本监控。
